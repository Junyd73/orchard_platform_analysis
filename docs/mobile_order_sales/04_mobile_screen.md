## 3. 주문 목록

필터: 검색(고객·번호) · **주문상태** (ST01: 예약접수~취소, DEC-011 CLOSED) · 기간.  
이행상태 필터는 계산값 (미배정/부분배정/배정완료/출고완료). ST01과 한 콤보로 섞지 않음.

카드 필드:

| 표시 | 소스 |
|------|------|
| 고객 | `custm_nm` |
| 주문일 | `order_dt` (표시 KST 날짜, 파싱 혼재 허용) |
| 출고예정일 | `MIN(planned_dt)` |
| 주문상태 | `status_cd` 명칭 (매핑 전 코드 원문 가능) |
| 재고상태(이행) | **단계 3 전 표시하지 않음** (허위 배정상태 금지) |
| 주문수량 | `SUM(qty)` |
| 주문금액 | `tot_order_amt` |
| 선입금 | `pre_pay_amt` (전표 아님) |

행 탭 → 상세. FAB → 등록.

## 4. 주문 등록/수정

- 고객 (이름·연락처 필수)
- 주문일 기본 `today_ops` → 저장 `YYYY-MM-DD`
- 출고예정일 (`planned_dt`)
- 시즌 `SS01`
- 상품 N행: 품종 · 중량 · 등급 · 크기/과수 · 수량 · 단가 · 금액
- 배송: 방문 / 택배 / (필요 시 화물)
- 방문수령 시 주소 비필수
- 선입금(금액만) · 메모

**검증:** 고객, 상세 ≥1, 행 수량 = 배송계획 합.  
**재고 0이어도 저장.** 가용 부족은 경고만.  
저장 시 판매 행 없음, `allocated_qty=0`.

수정: `stock_status='Y'` 이면 거부.

---

## 5. 주문 상세

헤더: 번호 · 고객 · **주문상태** · **재고상태(이행)** · 시즌 · 금액 · 선입금

규격별 줄 예:

```
신고 / 15kg / 특 / 25과
주문 20    배정 8    미배정 12    출고 0
```

내부 계약: 「배정」= `allocated_qty`(누적). 「출고」= `shipped_qty`. 사용자에게 누적이라는 말을 쓰지 않음.

배송 목록. 입금: 주문 선입금 + (판매 후) 수금 합.

출고 영역: `reserved_unshipped`만. 미배정만 있으면 출고 CTA 비활성.

액션: 배정 · 배정해제(`release <= 배정-출고`) · 출고확정 · 취소(출고 전만)

부분출고 후 판매 탭에 판매가 여러 장 보인다 (DEC-017: 출고 1회 = 판매 1건). 연결 조회는 `t_sales_master.order_no`.

주문상태와 재고상태를 한 배지로 합치지 않음. ODS `OdsCard` 메타 두 줄 또는 칩 두 개.

## 6. 판매 탭 (1차: 화면 구조)

| 필터 | 조건 |
|------|------|
| 가락 초안 | `AUCTION_RT` + `DRAFT` |
| 확정 판매 | `CONFIRMED` |
| 소매 | `order_no` 있음 |
| 수출/도매 | 주문 없음 · source ORDER |

카드: 판매번호 · 일자 · 고객/법인 · 금액 · 미수 · DRAFT 배지.

상세: 규격 줄 · 배송 · 수금(CONFIRMED만) · DRAFT면 **판매확정** CTA (PC에도 동일 서비스).

직접 판매: 고객 · 규격 · 수량 · 단가 · 배송 · 출고 포함.

한 주문에서 부분출고가 여러 번이면 판매 탭에 **판매 N건**이 같은 `order_no`로 나타난다. `t_order_master.sales_no`로 목록을 만들지 않는다.
